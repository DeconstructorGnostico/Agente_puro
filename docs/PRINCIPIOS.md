# Principios del «Sistema Perfeccionado» → especificación técnica

Este documento traduce los axiomas filosóficos del Sistema Perfeccionado (Adrian Mendez Millan) a
**reglas verificables por código**. Cada fila dice qué significa el principio para el software,
dónde está implementado y qué prueba falla si se rompe. Lo que no se puede medir no se declara.

Las pruebas están en `tests/`. Ejecuta `pytest -q` para comprobarlas todas.

## Lo que estos principios NO significan en el código

- **«Auto-validación» no es autoaprobación.** En software, validarse a sí mismo es el error que la
  arquitectura corrige: el resultado lo valida algo distinto de quien lo produjo.
- **«Consecuencia inmediata / auto-extinción» no es borrar ni apagar el sistema.** Es detener el
  ciclo afectado (HALT) y registrarlo. Un apagado global permanente era un bug de omega_brain y se quitó.
- **«Brevedad = Verdad» no se usa para decidir verdad.** Una respuesta corta puede ser falsa; la
  verdad la deciden la evidencia y la verificación independiente.
- **La intención coherente no basta.** Una persona puede afirmar algo coherente y falso
  («La Tierra es plana.» es coherente); sin evidencia queda `UNDETERMINED`.

## Resultado medido

Ver `docs/RESULTADOS.md`. En la última corrida, `stable_ratio` fue 1.0 en las pruebas y no hubo
violaciones de invariantes en las 2,712 peticiones held-out de la evaluación de V11 (todas las salidas pasan por `check_cycle`; ver `eval/results/summary.json`, campo `invariant_violations`).
